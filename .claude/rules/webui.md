# OPEN//77 WebUI — игровые экраны

- На старте задачи прочитай `open77.lua`, клиентский Lua-код создания страницы, веб-HTML/CSS/JS и список событий `Open77.on/emit` ↔ `page:on/send`. Не меняй контракт клиента/сервера ради нового макета.
- **Личная вкладка имплантов `rp_inventory_ui` одобрена владельцем**. Не переделывай её при работе над хирургическим терминалом `rp_surgery_ui`; это разные экраны и разные потоки.
- Структуру слотов, ID DOM, `Open77.on`, доступные действия и состояние из сервера сохраняй. В inventory — сетка разногабаритных предметов, drag/drop, R, ПКМ, оружие, пояс, обыск и кибердека. В surgery — выбор пациента/слота, установка/снятие/замена, согласие, мини-игры, таймер.
- Графический концепт — **не функциональная страница**. Иллюстрации и спрайты (по возможности прозрачные и без надписей) — отдельные ресурсы, зарегистрированные в `web_files`. Текст, стоимость, предметы и статусы — DOM, наполненный реальными данными, не запечённый в картинке.
- Текущий `rp_surgery_ui/web/assets/patient-hologram.svg` в GitHub является простым векторным ассетом. Владелец испытывал более детальную локальную версию (PNG внутри SVG), которая могла **не быть закоммичена**. Перед изменением/checkout сравни локальный файл с HEAD и не затирай арт.
- В `rp_surgery_ui/web/index.html` имеется режим **«Голограмма / Схема»**. Для голограммы код текущего `highlightSlot` показывает локальные ретикулы `#r-holo-targets`, не накладывая анатомические `#r-skin` на другую по пропорциям картинку. `surgery-redline.css` содержит несколько последующих поправок; при правках учитывай cascade и проверяй последние правила.
- В мини-игре снятия особенно защищай JS `cutPoints[i]` (Lua 1-based → JS 0-based): иначе маркеры последнего провода исчезают. Не «улучшай» UX, делая подсказки, обходящие проверку порядка.
- Проверяй `node --check` для JS (вынести inline JS во временный файл, если нужно), отсутствие дублирующихся ID, наличие указанных ресурсов, вид без прокрутки при 1920×1080, затем 1600×900 и 2560×1440. Тест в браузере — полезен, но не заменяет запуск в игровом WebUI.
- Дизайн должен быть художественно цельным, не прототипным; но игровые данные и интерактивность важнее декоративного HUD. Делай бэкап перед большой правкой и требуй реальную игровую визуальную приёмку.
