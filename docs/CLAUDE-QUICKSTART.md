# Как продолжить OPEN//77 RP в Claude Code (VS Code / Windows)

Дата подготовки: 2026-11-01. Настройка ориентирована на локальную рабочую копию владельца; этот документ не требует никакого токена или дополнительной интеграции.

## Старт с существующего репозитория

1. В VS Code выбери **File → Open Folder** и открой **корень** клона `open77-rp`, где находятся `CLAUDE.md`, `server.jsonc` и `resources/rp`. Не открывай только отдельную папку `web`: так потеряется часть инструкций и контекста.
2. Убедись, что установлено и авторизовано расширение **Claude Code**. Новые зависимости Node/Python для работы с исходным проектом сами по себе не требуются.
3. В терминале VS Code проверь:
   ```powershell
   git status --short --branch
   git log -5 --oneline
   git remote -v
   ```
4. **Если есть незакоммиченные изменения**, не делай `git pull` или `git checkout` вслепую. Особое внимание `resources/rp/rp_surgery_ui/web/assets/patient-hologram.svg`: локальный детализированный арт может отличаться от того, что в GitHub.
5. Если дерево чистое и текущая ветка `main`, можно обновить:
   ```powershell
   git pull --ff-only origin main
   ```
6. Открой новый диалог Claude Code **из корня проекта**. Claude автоматически читает `CLAUDE.md`. Ссылку на актуальный handoff ему можно дать явным первым сообщением.

## Рекомендуемое первое сообщение Claude Code

> Изучи корневой CLAUDE.md, HANDOFF-CLAUDE.md и PROJECT_CONTEXT.md. Сверь описания с актуальным кодом, git status, последними коммитами и локальными файлами. Особенно проверь отличие локального patient-hologram.svg от GitHub. Сначала кратко расскажи: архитектуру, принятый дизайн вкладки имплантов, текущее состояние интерфейса Риперов, незавершённые тесты. Ничего не меняй до моей следующей задачи.

## Где искать системы

- `rp_core` — аккаунты/персонажи/роли; `rp_factions` — постоянная фракция.
- `rp_inventory` + `rp_inventory_ui` — сетка инвентаря, личная вкладка имплантов; утверждённый дизайн не переделывать.
- `rp_cyberware` — серверные импланты, сканер, эффекты; `rp_cyberware_ui` — отдельный NPC Ripper/Kiroshi.
- `rp_surgery` + `rp_surgery_ui` — хирургическая операция, согласие, выбор слота и мини-игры. Это последний UI-проект, см. `RIPPER-UI-REDESIGN.md`.
- `rp_contracts` + `rp_contracts_ui` — заказы Фиксеров; нуждаются в игровом/транзакционном тестировании.
- Полная карта: [RESOURCE-MAP.md](RESOURCE-MAP.md).

## Быстрая проверка и запуск на ПК владельца

```powershell
# В корне проекта:
git diff --check
# Статические проверки (только если инструменты установлены):
# luac -p resources/rp/rp_surgery/server/main.lua
# Встроенный JS из index.html при необходимости сначала извлечь во временный .js,
# затем проверить node --check путь-к-временному-файлу.js
```

- Запуск сервера через `Start-Logged.cmd`; лог **локально** в `logs/server.log`, предыдущий в `logs/server.prev.log`.
- После нового клиентского WebUI, Lua или манифеста: серверный `refresh` / полный перезапуск и переподключение клиента, а не только `restart rp_surgery_ui`.
- Сценарии двух игроков: [TESTING-2P.md](../TESTING-2P.md). Не меняй баланс, снимай/устанавливай дорогой хром или создавай реальные финансовые транзакции ради теста без согласия владельца и бэкапа.

## Что не передаётся автоматически

- Локальные пользовательские правки, незакоммиченные ассеты и логи сервера **не появятся в GitHub** до коммита и пуша; Claude Code на той же машине сможет прочитать их из локальной копии с твоего разрешения.
- Экспорт старого чата Codex со скриншотами не загружен в репозиторий. Существенные выводы перенесены в `HANDOFF-CLAUDE.md` и UI-документы; при необходимости анализа каждой команды Codex отдельно передай экспорт в Claude.
- Бинарники сервера, системные `resources/system`, `.open77`, лицензии, ключи и логи намеренно не включаются в Git.

## После новой задачи

Сохраняй исходники в `design-backups` до крупных UI-переделок; не меняй `CLAUDE.md` на каждый косметический фикс. Актуализируй `HANDOFF-CLAUDE.md` после важных решений, `DOCS.md` при новых правилах/командах и `TESTING-2P.md` после подтверждённых тестов.
