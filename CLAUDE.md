# OPEN//77 RP — инструкция для Claude Code

> Актуализировано: **2026-11-01**. Репозиторий `foozys/open77-rp`, основная ветка `main`.
> Это **рабочие инструкции**, которые Claude Code читает автоматически. Подробные факты — в [HANDOFF-CLAUDE.md](HANDOFF-CLAUDE.md), архив принятых решений **без потерь** — в [docs/PROJECT_HISTORY.md](docs/PROJECT_HISTORY.md).

## При каждом новом сеансе

1. Прочитай [HANDOFF-CLAUDE.md](HANDOFF-CLAUDE.md) и относящиеся к задаче исходники. Если задача касается дизайна, дополнительно изучи [UI-REDESIGN.md](UI-REDESIGN.md) или [RIPPER-UI-REDESIGN.md](RIPPER-UI-REDESIGN.md).
2. Проверь `git status --short --branch`, `git diff`, `git log -5 --oneline`; локальные файлы могут быть новее GitHub. Не стирай и не заменяй незакоммиченные файлы. При расхождении документации и исходников выясни причину, а не выбирай вслепую.
3. Выполняй **только текущую задачу владельца**. Идеи из старой истории не являются поручением. Если заказана реализация — делай рабочие изменения и доступные проверки, не ограничивайся абстрактным планом.
4. Общайся на **русском**, включая UI/сообщения игрокам. Объясняй конкретно, что сделано и что ещё не протестировано. Не утверждай, что изображение, код или ресурс в Git, если он только на локальном ПК.
5. Владелец предпочитает изменения **непосредственно в `main`** без PR/feature-веток. При этом сначала защити незакоммиченные изменения, не применяй `reset --hard`, `clean -fd`, force push и массовые откаты без отдельного разрешения.

## Платформа и архитектура

- **OPEN//77 / Cyberpunk 2077, НЕ FiveM.** Не выдумывай Lua API, natives, exports, события, permissions и поддержку форматов. Проверяй по локальному devkit / [open2077.net](https://open2077.net/), манифестам `open77.lua` и рабочему коду.
- Серверная/клиентская логика — **Lua**, интерфейсы — HTML/CSS/JavaScript через `Open77.webui`; постоянное хранилище — **MariaDB**. Клиентская часть `*_ui` не должна зависеть от чисто server-only ресурса (иначе `resource_activation_failed`).
- `resources/rp/rp_core`: аккаунты (ключ `license`), персонажи (стабильный `characterId`), роли, whitelist, готовность/спавн, миграции. `playerId` — временный ID сессии.
- `rp_factions` и `rp_jobs` — независимые системы. Фракция Риперов не тождественна работе `ripperdoc`.
- `rp_money`, `rp_inventory`, `rp_shops`, `rp_contracts`: экономика и предметы. Изменение денег/предметов через системный `open77_transactions`, с серверной валидацией и защитой от повторов; не заменяй транзакции прямым SQL.
- `rp_medical`, `rp_police`, `rp_cyberware`, `rp_surgery`, `rp_vehicles`, `rp_taxi`, `rp_player_ids`: игровые системы. UI ресурсы `*_ui` располагаются отдельно.
- `server.jsonc` определяет порядок загрузки и путь ресурсов; `resources/system` — внешние системные модули и **не версионируется**. Не включай их в Git.

## Два разных интерфейса имплантов — не путать

1. **Личный инвентарь и вкладка «Импланты»**: `resources/rp/rp_inventory_ui/web/index.html`. Текущую реализацию имплантов владелец **одобрил** после работы Astra/Codex. **Не изменяй её дизайн или механику без прямой просьбы.** Сеточный инвентарь Tarkov-style (разные габариты, drag/drop, R, ПКМ, пояс, экипировка) тоже обязан остаться рабочим. См. [UI-REDESIGN.md](UI-REDESIGN.md).
2. **Хирургический интерфейс Риперов**: `resources/rp/rp_surgery_ui/web/index.html` + `surgery.css` + `assets/implants/body-v1.png`, `icons-v1.png` (те же ассеты, что во вкладке «Импланты» инвентаря); серверная операция — `rp_surgery`, киберимпланты — `rp_cyberware`. Экран Рипера: группы слотов, анатомия, выноски и правая панель «Наряд на операцию» (снятие/установка/замена без модального окна); затем согласие пациента и две мини-игры. Сохраняй `surgery:*` события, предупреждения, клики и последствия неудач. См. [RIPPER-UI-REDESIGN.md](RIPPER-UI-REDESIGN.md).
3. **Голограмма Риперов (2026-11-01):** прежняя тема `surgery-redline.css`, `patient-hologram.svg` (в т.ч. локальная PNG-версия владельца) и переключатель «Голограмма / Схема» убраны из ресурса в пользу стиля вкладки «Импланты». Полная копия прежней версии — `design-backups/rp-surgery-ui-20261101-before-implants-style/`. Игровая приёмка нового экрана ещё нужна (см. [TESTING-2P.md](TESTING-2P.md)).

## Как безопасно изменять

- Сначала узнай границы ресурса: `resources/rp/<имя>/open77.lua` (permissions, dependencies, `web_file(s)`), Lua клиент/сервер, WebUI HTML/JS и события. Не придумывай лишние серверные поля ради макета.
- **Реальные данные важнее концепта**: дизайн с фиктивными предметами, здоровьем или валютой — только референс, не фон, подменяющий серверный state. Графика должна быть отдельными ассетами с прозрачностью; интерактив — в DOM.
- Вся бизнес-валидация на сервере: `source`, права, персонаж, дистанция, текущий слот, инвентарь, согласие, дубли и повторная отправка. Не упрощай хирургическую механику ради новой вёрстки.
- Референс/прошлая версия сохраняются в `design-backups/`. Не редактируй и не удаляй резервные копии.
- Публично доступные репозиторные файлы не должны содержать API ключи, пароли, токены, приватные логи, .env, .open77, дампы БД, бинарники или содержимое `resources/system`.
- Статические проверки (JS, Lua, DOM, manifest, CSS) не заменяют проверку в игре, особенно с двумя игроками. Сначала `git diff --check`, затем доступные локальные проверки, потом ручной сценарий.

## Локальная эксплуатация

```bash
git status --short --branch
git pull --ff-only origin main   # только при чистом рабочем дереве и отсутствии конфликтов
```

На Windows `Start-Logged.cmd` перед стартом делает бэкап базы в `backups/` и ротацию логов (`tools/ops/prestart.ps1`), пишет серверный вывод в `logs/server.log`, прошлый — `logs/server.prev.log`. Перед коммитом — `node tools/ops/check-static.cjs`. Ничего привязанного к ПК в коде: адреса — convar'ы, ключи и режимы (`testMode`, `corporateKey`) — tunables; схема БД — только миграциями `rp_core:migrate`. Они локальны и в Git не входят. Для публикации обновлённых WebUI/клиентских ресурсов и манифестов нужен `refresh` / полный перезапуск сервера и **повторное подключение клиентов**; одного `restart` недостаточно.
