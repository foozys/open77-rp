# RP-сервер на OPEN//77 (Cyberpunk 2077)

Это сервер OPEN//77 сборки 2.50.0+op77.168, изначально дистрибутив Freeroam. Переделываем его в RP-сервер с нуля. Общаемся с пользователем на русском.

## Принятые решения
- **Подход — гибрид.** Своё ядро пишем сами (персонажи, роли, конфиг, логи, миграции БД). Деньги и предметы храним через платформенный `open77_transactions` (лежит в `system/` репозитория open77-resources). Работы и системы мира пишем сами. Пак `rp/` из https://github.com/Open2077/open77-resources (MIT, экспериментальный, сгенерирован ИИ, на французском) используем только как справочник подходов и не подключаем целиком.
- **Язык:** только русский. Исключение: экран ошибок OPEN//77 (отказ во входе, кик) не рисует кириллицу, поэтому такие тексты идут через `Util.kickText`, который транслитерирует их в латиницу. **Лор:** строгий (whitelist, анкеты).
- **Тесты:** у пользователя есть второй человек, механики для двух игроков проверяем вдвоём.
- **Ключ персонажей в БД:** идентификатор `license` (`GetPlayerIdentifierByType(p, "license")`), строкой. Не `userId`, не `playerId`, не имя.
- **Whitelist:** анкета одна на аккаунт; после одобрения (`rp.whitelist add`) персонажей игрок создаёт сам. Админы с ACL `rp.whitelist.bypass` проходят всегда.
- **Админ-роли:**
  - Хранятся в `rp_staff` по `license`. Права проверяет `Roles.can`, а не ACL `command.<имя>`. Команды открыты всем, при нехватке прав отвечают отказом.
  - Лестница и права задаются в `RpConfig.staffRoles`: хелпер → модератор → администратор → руководство. Старшая роль получает права младших.
  - ACL — запасной ключ: право из `acl.jsonc` проходит любую проверку, `rp.owner` ставит выше всех ролей. У владельца там `*`.
  - Наказывать и назначать роли можно только тем, кто ниже по уровню.
  - Другие ресурсы проверяют права через экспорты `can(playerId, perm)` и `staff_role(playerId)`.
- **Деньги:**
  - `open77_transactions` скопирован из репозитория open77-resources (ветка `next`) в `resources/system/`. Каталог `system/` вне нашего git: при обновлении сервера ресурс нужно поставить заново.
  - `rp_core` регистрирует у него поставщика субъекта (экспорт `tx_subject`). Поэтому кошельки принадлежат персонажу: `cash:rpc-<id>` и `bank:rpc-<id>`.
  - Ресурс `rp_money`. Деньги выпускаются из `sys:rp.money` по правилу оператора: `tunable.set open77_transactions mint1 rp_money sys:rp.money money 2000000`.
  - Стартовые деньги выдаются один раз; отметка в `rp_money_start`, потому что журнал транзакций чистится через 90 дней.
  - Зарплата: `opId` вида `rppay:<персонаж>:<период>`.
- **Инвентарь — сетка (пожелание пользователя):**
  - Предметы занимают прямоугольник клеток, их двигают мышью и поворачивают на R.
  - Количество хранит `open77_transactions` (`char:rpc-<id>`), и оно главнее. Раскладку по клеткам хранит `rp_inventory` в таблице `rp_inventory_layout`; при расхождении её сверяет `Grid.reconcile`.
  - Каталог предметов: `rp_inventory/server/config.lua`.
  - Выдача предметов из `sys:rp.items` требует правило оператора: `tunable.set open77_transactions mint2 rp_inventory sys:rp.items * 5000`.
  - Выброшенное становится кучей (`pile`) `open77_containers`. Ресурс тоже скопирован в `resources/system/`, вне нашего git.
  - Окно — ресурс `rp_inventory_ui`, клавиша I.
- **Работы (`rp_jobs`):**
  - Организации и ранги задаются в `rp_jobs/server/config.lua`, старший ранг наследует права младших. Право `job.manage` даёт найм, смену ранга и увольнение тех, кто ниже.
  - У персонажа одна работа, хранится в `rp_character_jobs`. Смена хранится только в памяти: после входа персонаж всегда не на смене.
  - Зарплату платит `rp_money`. Сотрудник получает зарплату ранга только за смену; без смены — ничего. Безработный получает пособие.
  - Кто платит: `payFrom = "state"` — выпуск из `sys:rp.money`; `"society"` — касса `soc:<работа>`, её пополняют командой `rp.society`.
  - Другие ресурсы спрашивают через экспорты `job`, `can(playerId, perm, requireDuty)`, `on_duty`, и получают события `rp_jobs:duty` и `rp_jobs:changed`.
- **Слоты персонажей:** tunable `maxCharacters`, по умолчанию 1.
- **Внешность — `open77_appearance`** (системный, не форкаем). Хранит по `user_id` установки + `character_key`; персонажа выбираем через `TriggerEvent("open77:appearance:setCharacter", playerId, key)`. Создать нового персонажа (редактор) можно только при входе, до загрузки мира: поздний `createRequired` клиент игнорирует. Переключение на существующего работает и в игре.
- **Выбор персонажа:** сервер выбирает персонажа до загрузки мира (`next_character_id` → последний сыгранный → незаконченный → новый слот) и передаёт ключ `rp-<id>` в `open77_appearance`. После загрузки `rp_core` держит readiness gate (`participate` + heartbeat от клиента) и показывает экран выбора или анкету (ресурс `rp_charselect`: WebUI, камера, локальные манекены) в приватном bucket. При одном слоте и одном готовом персонаже экран пропускается. «Создать» и персонаж без внешности на этом ПК — через перезаход.
- **Особенности платформы, найденные на тестах:**
  - Клиент спрашивает внешность сразу после загрузки ресурсов. Поэтому персонажа выбираем ещё в `onPlayerConnecting` по `userId` через `rp_account_identities` и отдаём ключ первым делом в `onPlayerConnected`.
  - `worldReady` приходит до появления тела. Мир готов только при `characterBootstrap().playerReset == "complete"`.
  - Своё тело от первого лица рисуется без головы, поэтому в анкете показываем манекен.
  - Тело для манекена берём из `open77:appearance:body`. Клиентский `captureBody` давал не ту внешность.
  - Одежду гардероб (F2) хранит в `open77_character_presentation`.
  - При смене пола тело пересоздаётся, телепорт нужно повторять.
  - Экран ошибок OPEN//77 не рисует кириллицу.
  - Клиентская часть ресурса не может зависеть от чисто серверного ресурса (`rp_core` и др.): вход обрывается с `resource_activation_failed` (`missing_dependency`). Клиентский код выносим в отдельный `*_ui` без таких зависимостей.
  - Новые или изменённые клиентские файлы доходят до игроков только после `refresh` в консоли сервера (или перезапуска) и перезахода; `restart <ресурс>` их не публикует.
  - В параметрах SQL не должно быть `nil`.
- **Вход на свой сервер:** через Direct Connect к `127.0.0.1:11778`. Ссылки `open77://connect?server=<id>` для unlisted-серверов лаунчер игнорирует. После смены лицензионного ключа нужна повторная регистрация: `enrollmentConfirmed: false` в `.open77/master-identity.json` и удаление `.open77/resource-cache`.

## Документация
`DOCS.md` — документация для владельца и администрации: что сделано, команды и права, настройки с примерами, файлы конфигурации, таблицы БД. Обновлять её при каждом новом ресурсе, команде, настройке или правиле выпуска.

- Этап 2 написан полностью.
- Этап 3:
  - Магазины: `rp_shops` и `rp_shops_ui`.
    - Точки ставит администрация (`rp.shop add`); подсказки строятся через `open77_interactions` (`create` по позиции).
    - Торговые автоматы — тоже точки администрации (тип `vending`). Проверено в игре: у устройств класс `gameDeviceBase` (команда `/rp.classes`), так что автоматы по классу не отличить.
    - Товар выпускается по правилу `mint3`.
    - Подсказки `open77_interactions` не показывают кириллицу, поэтому надписи на них на английском.
  - Машины: `rp_vehicles` и `rp_vehicles_ui`.
    - Машина — строка `rp_vehicles` (владелец — персонаж), состояние — `Open77.vehicles.getProperties` в JSON.
    - Автосалоны и гаражи — точки администрации; у гаража отдельное место выезда.
    - Выгнанная машина «в городе» (`state = 'out'`, место `px/py/pz/ph/pbucket`), выгнать можно несколько. Она в мире, пока в игре хозяин или держатель подходящего ключа; ушёл последний — убирается (`sweep`) и появляется на том же месте при входе любого из них (`spawnFor`). Переживает рестарт.
    - Ключ — уникальный предмет `carkey` (`meta: vehicle, plate, gen`), выдаёт экспорт `rp_inventory:give_instance` (с ценой в той же операции). Смена замка увеличивает `lock_gen`. Хозяину ключ не нужен. Предмет с `use = "event"` не тратится и шлёт `rp_inventory:used(..., meta)`.
    - Домашний гараж `garage_id`: всё с машиной делается только там (позже гараж привяжется к дому или квартире). Покупка — ближайший к автосалону гараж. Хозяин может поставить в другой гараж — он станет домашним. NULL или убранный гараж — хозяину любой.
    - Держатель ключа в домашнем гараже может выгнать, поставить и эвакуировать машину; ключ и смена замка — только хозяину.
    - Эвакуация: владелец из гаража (платно), `/tow` для права работы `vehicle.tow` на смене, `rp.tow` для администрации.
    - Машину за руль не сажаем (решение пользователя). Записи моделей взяты из каталога `open77_admin`.
- **Наличных нет (решение пользователя, лор).**
  - Деньги — только счёт `bank:rpc-<id>`; `/pay` переводит со счёта на счёт. Банкоматов нет.
  - Из рук в руки деньги передаются **денежной щепкой** — уникальным предметом `credchip` с `meta.amount`.
    - `/chip <сумма>` записывает щепку: деньги уходят со счёта в `soc:rp.chipvault`.
    - «Вставить в нейропорт» тратит щепку и переводит сумму из хранилища обратно на счёт.
  - Старые наличные переносятся на счёт при входе.
  - Сетка инвентаря хранит экземпляры уникальных предметов как стопки с полем `u`.
- **Ранение и медики (`rp_medical`, `rp_medical_ui`)** — написано, не проверено в игре.
  - Смерть (`dead`, кроме `cause = "script"`) сразу превращается в «ранен»: `revive` на месте, неуязвимость, поза `wounded` (сидит, open77_animations), клиент блокирует Movement и оружие; freezeRotation/freezePosition не используем — блокируют камеру. Мёртвого игрока заморозить нельзя: платформа снимает блокировки управления при смерти (проверено в игре). Поднимает экспорт `raise` (медик, бригада, больница, `rp.heal`).
  - G — вызов медикам на смене (право `ems.basic`); нет никого — NPC-бригада через 90 с, поднимает на месте за плату (решение пользователя). H — больница через 5 мин за плату (`respawn` в точке `rp.hospital`). `/revive` — медик с `ems.revive` на смене.
  - Потери — только плата (решение пользователя); не хватает денег — списывается сколько есть.
  - Вышел раненым — отметка `rp_medical_downed`, при входе больница и плата.
- **Полиция (`rp_police`, `rp_police_ui`)** — написано, не проверено в игре.
  - Наручники, сопровождение, обыск — `open77_rp_basics`, скопирован из open77-resources в `resources/system/` (вне нашего git, при обновлении сервера ставить заново). Он пускает по ACL `rp.cuff`/`rp.escort`/`rp.search`; `rp_police` выдаёт их на смене через `Open77.acl.grant` (scoped `acl.grant:rp.cuff` и т. д. — валидатор devkit такие права не узнаёт, это нормально) и забирает со смены, при входе и выходе.
  - **`PoliceConfig.selfTest = true` сейчас включён** (тест в одиночку: владелец применяет к себе штраф, КПЗ, обыск). Перед запуском живого сервера — выключить.
  - Решения пользователя: КПЗ с таймером, срок идёт только онлайн; штрафы списываются сразу в `soc:ncpd`, не хватает — остаток долгом; обыск — инвентарь с двумя сетками, перетаскивание между ними (решение пользователя; `rp_inventory` экспорт `open_loot`, событие `rp_inventory:lootMove`, право на каждый перенос — экспорт `rp_police:loot_allowed`); `/911` с меткой.
- **Трафик** — платформенный `open77_traffic`, включён convar'ом в `server.jsonc`.
- **`Start-Logged.cmd`** пишет вывод сервера прямо в файл: через конвейер PowerShell сервер подвисал при большом объёме лога (трафик).
## Инструменты
- Devkit MCP `open77-devkit` подключён. Каждую native-функцию, permission и событие проверяй через него (`open77_api`, `open77_search`), не угадывай и не переноси имена из FiveM. После написания ресурса запускай `open77_validate`. Индекс MCP собран для +op77.156, а сервер +op77.168. При старте `open77_transactions` намеренно вызывает конфликт для самопроверки отката, и с .168 в логе остаётся строка `[ERR] ... SQL 1062`. Это не сбой, если следом идёт `ready: store=sql`.
- Документация: https://open2077.net/docs/ (есть `/llms-full.txt`).
- Правила платформы: сервер авторитетен. Не трогать игрока до `Open77.ready` и `onPlayerReady`, ID приводить через `tonumber`, не действовать на мёртвого игрока, проверять reason у каждого вызова. В манифесте указывать минимально нужные `permissions` и явные пути к скриптам (без `**` в `*_script`).

## План
**Этап 0 — инфраструктура**
1. git-репозиторий для своих ресурсов.
2. Лицензионный ключ из `server.jsonc` перенести в `OP77_LICENSE_KEY`.
3. MariaDB, база `open77` в utf8mb4, пользователь с минимальными правами, подключение через `OP77_DATABASE_CONNECTION`.
4. `npx -y @open2077/mcp types`.
5. Админ в `acl.jsonc`.
6. RP-список в `resources.load`: убрать freeroam, open77_freeroam, open77_cyberware_lab.

**Этап 1 — `rp_core`**
- Конфиг и логгер, утилиты для readiness/alive, миграции (`schema_version`).
- Аккаунты по `license` и баны.
- Персонажи: слоты, создание и выбор, внешность через `open77_appearance`.
- Спавн, сохранение состояния, роли и права.

**Этап 2:** экономика через `open77_transactions` и зарплата, инвентарь (WebUI), работы с рангами и duty, RP-чат (`/me`, `/do`, `/try`, OOC, радиус), HUD, админ-инструменты.

**Этап 3:** магазины и банкоматы, личные машины и гараж, первая профессия, NCPD на базе `open77_rp_basics`, смерть и медики. — закрыт (банкоматы отменены).

Purge (`sanityPerUse`, (`onHackingTransition` status_purged / interrupted с purge в reason) добавляют психоз за применение.

3. Механик как профессия: ремонт машин за плату (эвакуация уже есть).
4. Телефон: звонки, сообщения, банк, вызов служб.
5. Подработки без найма: доставка, такси, металлолом.

**Хвосты:** проверить в игре написанное в одиночку; заход с другом по TESTING-2P.md; перед запуском живого сервера — `selfTest = false` в `rp_police`.

Ограничения движка: нести или тащить игрока нельзя (нет привязки игрока к игроку). Поддерживается только MySQL/MariaDB, системы миграций нет.
